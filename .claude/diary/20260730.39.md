## What didn't
- Monitor stream (`mcx monitor`) exits with "no events or heartbeat for 90s" when there's a long silence between impl and review completion. Died 4 times this sprint. The 90s hardcoded timeout is too aggressive for long-running impl sessions. `mcx claude wait` in background mode is the reliable fallback.
- Accidental `review_round` inflation: clearing a stale `pending:` sentinel and re-running `mcx phase run review` increments `review_round` even though no real review ran. Required setting `review_round_retry=true` to unblock. Root cause: the correct fix for a stale pending sentinel is to clear it then go directly to `repair` (via `--from`), not re-run `review` again.
- Impl session for #341 hit 100 turns / $5.54 — the most expensive impl session in recent sprints. The `editTargetURL`/`baseImage` threading needed to connect the capture-frame path to `SlideshowView.swift`'s existing image pipeline was more invasive than the plan estimated.
- Leftover uncommitted changes in the main worktree after #342's impl session (the session pushed a second commit `1c6da1f` to origin but the local worktree still had those as uncommitted). Caused a `git checkout main` failure. Fixed by discarding with `git checkout --`; no data lost since origin already had the commit.

## Patterns established
- **When a `pending:` review sentinel is stale and the review verdict is already known (from session log), go directly to repair with `--from review` — don't re-run `mcx phase run review` first.** Re-running review increments `review_round` wastefully and risks hitting the max-round cap.
- **Use `mcx claude wait <id>` in `run_in_background: true` as the primary completion signal when the monitor keeps dying.** The 90s silence timeout makes the monitor unreliable for long impl sessions.
- **Joe's mid-sprint clarification about #326 (2026-07-30):** The compare-right-pane picker must use the `LazyVGrid` thumbnail grid view (`SlideshowView+Grid.swift`), not a list or bare file picker — noted on the issue.
