# Sprint 21 — 2026-07-02

Both planned issues shipped. This sprint's planning phase was unusually deep: two
Explore agents + one Plan/design agent investigated the codebase before a line of code
was written, producing a design doc (`/Users/joe/.claude/plans/zazzy-riding-starfish.md`)

title string, a genuine implementation slip).

## What worked

- **Deep upfront design for architecturally risky work.** #198 (compositing pipeline
  rewrite, touching 9 edit functions + the two core rendering functions) shipped with zero
  review findings — a first for this project's sprint history. The design doc's
  function-by-function change list meant the impl session wasn't inventing the approach as
  it went; it was executing a plan.
- **Manually cross-checking impl/review sessions against the sprint plan.** Neither
  `/implement` nor the review phase script reads `.claude/sprints/sprint-N.md` — they only
  see the raw GitHub issue and CLAUDE.md. For both issues this sprint, the orchestrator sent
  a follow-up message to the freshly-spawned impl session pointing it at the plan's specific
  design decisions, and manually augmented the review spawn prompt with the same
  cross-check. This caught a real key-binding conflict before any code was written (#168's
  issue text proposed `c`, already taken by flip) and a missing test the plan had explicitly
  flagged as a risk (#168's corner-rotation case). This is the second sprint in a row this
  gap has been worked around manually — see skill proposal below.
- **Resuming quota-interrupted sessions instead of discarding.** Both impl sessions and the
  #198 review session hit the usage quota mid-work, multiple times each. Two hits were
  zero-progress (cleanly discarded, re-spawned); the rest were partial-progress and were
  resumed in place via `mcx claude send` with no work lost. The existing quota-recovery
  procedure in `run.md` worked exactly as documented, including the "verify build before
  committing" step, which caught a real build failure (see below) before it was baked into a
  commit.
- **Proactively warning a session about a known gotcha before it hits it.** After #168's
  impl session lost time to the `project.pbxproj` registration gotcha (new files aren't
  auto-discovered — `slidey/` is a traditional Xcode group, not a synchronized root group
  like `Resources/`), the orchestrator included that exact warning in #198's initial redirect
  message, since #198 also adds a new file (`EditStack.swift`). #198's session registered it
  correctly on the first attempt.

## What didn't

- **Quota reset timestamps lagged reality twice.** `mcx status`/`quota_status` reported
  `resetsAt` timestamps that had already passed while utilization still read 100%. Both
  times this resolved itself on a recheck ~10-15 minutes later. Not a blocker, but cost real
  wall-clock time — worth a documented "if resetsAt has passed but utilization is still
  100%, wait ~15 min and recheck rather than retrying" note.
- **`/implement` and the review phase script don't read sprint plan files at all.** This is
  the second sprint in a row where a plan file contained load-bearing design decisions
  (Sprint 20: model I/O shapes and conversion gotchas; Sprint 21: the entire `EditStack` data
  model and a corrected key binding) that the automated skill/phase prompts never saw. The
  orchestrator compensating manually works, but is easy to forget and doesn't scale if a
  sprint runs unattended.
- **`project.pbxproj` registration for new source files is an unwritten trap.** Two sprints
  now (crop's `CropController.swift`/`SlideshowView+Crop.swift`, then this sprint's
  `EditStack.swift`) have needed this exact fix. It's now called out in CLAUDE.md-adjacent
  guidance ad hoc via orchestrator messages, but isn't written down anywhere a session would
  find unprompted.

## Patterns established

- **Deep multi-agent research before planning architecturally risky work pays off
  measurably** — compare #198 (zero review findings) to prior sprints' single-pass-review
  features. Reserve this level of upfront investment for issues that touch the compositing
  pipeline / other hot-path core functions, not routine feature additions.
- **When quota status looks wrong (resetsAt passed, utilization still 100%), wait and
  recheck rather than retry-spawning into a guaranteed failure.**
