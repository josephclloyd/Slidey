## What didn't
- **Automated GUI verification is not viable in this environment.** Attempted `cliclick` +
  `screencapture` to visually confirm the mask-preview fix myself before asking Joe to
  test. Two independent attempts (full-screen, then a computed-region capture from
  AppleScript-reported window bounds) both leaked Joe's Mail inbox, Finder sidebar, and
  System Settings windows instead of showing only Slidey — window-position math doesn't
  reliably resolve across displays/Spaces from this environment. Memory note filed
  (`feedback-no-automated-screenshots.md`); default to manual verification by Joe going
  forward for this project.
- **The `review_round` phase-state counter has no guard against quota-failed spawn
  attempts.** Twice this sprint, a `mcx phase run review` call spawned a session that
  immediately died with a quota error (0 tokens, no verdict) — but `review.ts` had
  already incremented `review_round` before the spawn, so the counter advanced toward the
  2-round cap on a round that produced zero actual review work. Both times required
  manually resetting `review_round` via `phase_state_set` before retrying. Left
  unaddressed, this would eventually cause a legitimately-still-in-repair item to hit
  "exceeded max review rounds" and land in `needs-attention` purely because quota hit at
  the wrong moment twice.
- **Static code reasoning alone got the Object Removal alignment bug half-fixed.** The
  first fix (mask preview positioning) was correct but insufficient — a second,
  independent bug (Y-axis inversion in the paint-to-pixel conversion) was only found
  because Joe actually painted a stroke and reported the exact symptom (drag down → paint
  goes up). Pure code comparison against the "known-good" `ImageDisplayView` pattern
  didn't surface this because the bug was in a code path (`objectRemovalViewToImagePixel`)
  that had no working analog to compare against in the codebase — `CropController`'s own
  formulas were the only precedent, and they don't touch a raw `CGContext`, so the
  Quartz-native-vs-view-coordinate mismatch had nothing to catch it before a human tested.
- **`done.ts`'s internal `git pull` detached HEAD once** (same known failure mode as
  Sprint 24) — recovered per the documented `git checkout main` fix, but it's still not
  fixed at the source.

## Patterns established
- **Quota-failed spawn recovery for review/repair rounds:** if `mcx claude ls` shows a
  spawned session died with 0 tokens/cost and no verdict, treat it as "no review actually
  happened" — reset the relevant `_round` phase-state key back down by one before
  re-spawning, rather than letting the phase engine count it as a real, consumed round.
  Proposing this as a `review.ts`/`repair.ts` fix below rather than leaving it as an
  orchestrator-memorized workaround.
- **GUI verification default for this project: manual, not automated.** Don't re-attempt
  `cliclick`/`screencapture` scripted verification here without Joe first providing
  explicit per-display/Space targeting info.
- **Post-merge live bug reports get fixed directly, not through the impl/review/repair
  pipeline.** When Joe reports a bug interactively in the same session (not a filed
  issue), diagnosing and fixing it directly — with build/test verification and a PR for
  his review — is faster and more appropriate than spinning up the full autonomous
  session machinery for a single, already-diagnosed fix.
