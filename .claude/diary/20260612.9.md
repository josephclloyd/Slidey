## What didn't

- **`Closes #N` missing from every single PR body** — all 5 impl sessions omitted it; added manually each time. This is now the 3rd consecutive sprint with 100% miss rate. The fix belongs in the impl skill, not the post-impl routine.
- **Main worktree drift on every impl session** — sessions ignore `--worktree` and branch in the main checkout, leaving HEAD on the feature branch after the session exits. Sprint 8 retro documented this; it still happened every time.
- **#58 first attempt hit quota before doing any work** — the session spawned, read CLAUDE.md, branched, and immediately hit the extra usage cap. No work lost, but wasted ~$0.51 and ~10 min waiting for the reset.
- `prNumber` consistently null on first `mcx tracked --json` check after re-pair — always needed a second check after the daemon's next poll cycle.

## Patterns established

- Run the monitor with a grep filter (`session.result|ci.finished|pr.merge_state_changed|work_item.phase_changed`) from the start — `--subscribe session,work_item` is too broad and triggers rate-limiting suppression.
- Start review sessions immediately after impl `session.result` arrives; don't wait for CI. They finish in parallel and the done phase handles CI gate.
- After an impl session completes, always check `git branch --show-current` before attempting `git checkout main` — the session may still have branched in main even when `session.result` shows it as idle. Wait for `mcx claude ls` to confirm idle.
