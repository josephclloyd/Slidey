## What worked
- Serializing all five issues in one `addBlockedBy` chain (per plan.md's hot-file rule)
  avoided any `SlideshowView.swift` merge conflicts, even with five separate feature
  branches touching it across the sprint.
- Sending impl sessions the sprint plan excerpt manually via `mcx claude send` (the
  workaround identified in Sprint 22's retro) worked cleanly for both #209 and #102 — no
  sessions missed plan context this time.
- The round-2 review catching #102's main-thread-blocking bug and the repair session
  fixing it correctly on the first attempt is the pipeline working as designed: real bug,
  caught, fixed, verified, merged — no manual intervention needed beyond the normal loop.
- Filing #216 for the flaky `DirectoryMissingTests` CI failure rather than stopping to
  investigate live kept the sprint moving — the next CI run on the same commit history
  already proved it wasn't a regression, so live investigation would have been wasted time.

## What didn't
- **#206's impl session hit the extra-usage quota mid-task**, leaving an uncommitted,
  partially-finished branch (`file-menu-disabled-state`) in the main checkout. Recovery
  went smoothly following run.md's partial-progress procedure, but the session's leftover
  work included unused, unwired `@FocusedValue`/`imageLoaded` plumbing added to
  `EditMenuCommands` — out of #206's stated File-menu-only scope and never connected to a
  `.disabled()` call. This is the first time recovered impl-session code needed a scope
  trim (dead-code removal) before it could be committed, rather than just being finished
  as-is. Caught by reading the diff before committing, not by any automated check.
- **PR #213's merge to `main` failed CI once** on an unrelated flaky filesystem-watcher
  test (`DirectoryMissingTests.testDirectoryRecoveryAfterReappearing`, timing-sensitive
  `wait(for:timeout:)` on a `DispatchSource` watcher). Confirmed non-blocking by observing
  the very next push's CI run (same test suite, same recent history) pass cleanly — filed
  as #216 instead of chasing it live.
- Two `mcx` CLI syntax mismatches cost small amounts of orchestrator time this sprint:
  `mcx track` wants a bare issue number (`mcx track 133`), not `#133` — the `#`-prefixed
  form errors with "Invalid number". And `mcx work-item state set` (as written in run.md)
  isn't a real CLI command — the actual mechanism is `mcx call _work_items
  phase_state_set '{"workItemId":...,"repoRoot":...,"key":...,"value":...}'`. Both were
  discovered by trial and error this sprint; run.md's examples should be corrected.

## Patterns established
- Trimming unused/unwired code left behind by a quota-interrupted impl session, rather than
  either discarding the whole branch or committing it as-is, is now a validated recovery
  step: read the diff, check every new symbol is actually referenced, remove what isn't
  before the build/test verification and commit.
- Confirming a CI failure is non-blocking by checking whether the *next* push on the same
  history passed (rather than re-running or investigating the failing commit directly) is
  a fast, reliable way to distinguish flakiness from regression when the failing test is
  unrelated to the PR's diff.
