## What worked

- **Serialising #16 → #18**: #18's test target was added after #16 merged, so tests cover
  the completed `auto-open-recent` code. No merge conflict.
- **Polling loop** (`mcx claude ls --json` every 30 s): monitor streaming still unavailable;
  polling continues to be the only practical session-tracking mechanism. Robust enough.
- **Review sessions posting LGTM comments**: GitHub self-approve restriction means review
  sessions can't formally approve their own PR, but posting a LGTM review comment satisfies
  the intent. CI is the real gate.

## What didn't

- **`mcx restart _claude` failed again**: "server was disconnected and cannot be
  auto-reconnected". Workaround: `kill <pid>` then `mcpd --background`. This is the same
  failure as Sprint 1. The patch-compat workaround works (downgrade symlink to 2.1.128,
  restart daemon), but the `mcx restart _claude` sub-command itself is unreliable.
- **Sprint worktree diverged from main**: The sprint-2 worktree was branched before #24
  and #25 landed. Review commit required an explicit `git merge origin/main` before staging
  the version bump — not documented. Led to a version bump applied to a stale
  `project.pbxproj` until caught.
- **Mixed MARKETING_VERSION values**: The test target (#25) initialised at `1.0` while the
  app target was at `1.1`. The review.md sed command used a hardcoded old version; a
  version-agnostic sed is needed.

## Patterns established

- Review commit step must `git merge origin/main` in the sprint worktree before touching
  `project.pbxproj` — sprint worktree is always behind main after feature PRs merge.
- Use a version-agnostic sed for the MARKETING_VERSION bump (e.g. `s/MARKETING_VERSION = [0-9.]*;/MARKETING_VERSION = X.Y;/g`).
- `mcx restart _claude` is unreliable; document fallback (`kill <pid>` + `mcpd --background`)
  in the patch-compat reference.
