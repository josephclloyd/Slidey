# Sprint 15 — 2026-06-26

## What was done
- #142 Fixed music autoplaying regardless of the "Resume music when starting slideshow" setting
- #143 Added defensive guard ensuring slideshow never auto-starts on launch
- #126 Added 2x and 4x AI upscale options with separate key bindings (U / ⌥U / ⇧U)
- #105 Added Cmd+Z undo support for Move to Trash and Rename operations

## What worked
- Bugs-first ordering: fixing #142 and #143 before the enhancements meant the repair context was fresh and the fixes were tight
- #142 repair correctly caught that the "gate behind autoPlayMusic" approach was insufficient — the repair session adopted the cleaner design (removing activate() calls entirely from non-slideshow handlers) without prompting
- Review sessions caught the #142 partial-fix correctly and articulated the spec violation clearly
- #105 went clean first pass despite NSUndoManager being the most complex API used this sprint
- New issues backlog grew from 4 to 18 during planning — sprint 15 started with a healthy pipeline

## What didn't
- Two quota hits (on #126 and #105 first attempts) added ~4h of dead wall time; both were zero-progress cases (build failed / no commits) so recovery was clean
- #126 shipped a regression (#149): 2x upscale produces corrupted/jumbled output on some images — tile assembly or model mismatch at `-s 2` vs `-s 4`; not caught by review because it requires running the actual binary on real images
- Sprint ran across two calendar days due to quota hits

## Patterns established
- Music activation should be tied exclusively to slideshow start (toggleSlideshow), not to lifecycle events (directory open, fullscreen entry) — baked into #142 fix; document in CLAUDE.md gotchas
- Quota hits at the start of a session leave zero-progress (no commits, failing build) — discard cleanly and re-spawn; do not attempt partial recovery
- Post-impl check: build output from the result summary doesn't confirm tests passed — check the PR directly (`gh pr checks`) when the result text is ambiguous
