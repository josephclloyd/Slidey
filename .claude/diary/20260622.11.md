## What didn't

- **Quota hit on #81 impl** — 5h window hit 98% mid-session, extra usage disabled, session exited after only adding one notification name constant. Partial work was committed to the branch and the session resumed after the window reset (~3.5h gap). Total added ~3.5h to wall time.
- `gh pr view --json state` returned HTTP 401 after the long quota-reset gap — auth token had expired. REST API fallback (`gh api repos/.../pulls/N`) worked fine.
- `gh auth refresh` requires interactive browser flow; can't be automated in headless sessions.

## Patterns established

- When a quota hit leaves a branch with only partial work, commit what's there and push — the impl session will continue from the saved state rather than starting over.
- After a long gap (quota wait), check token expiry before using `gh pr view --json`; fall back to `gh api repos/.../pulls/N` if needed.
- Spawning the next serialized issue as soon as its blocker merges (not waiting for all parallel work to clear) keeps the pipeline moving.
