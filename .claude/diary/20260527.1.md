- `mcx phase run` for a second call on the same issue returns `in-flight` with a pending
  sentinel — the orchestrator must execute the spawn from the *first* call's output, not
  re-call `phase run` to get the command again.

## Patterns established
- Always restart the `_claude` mcx server after changing the `claude` symlink — the daemon
  caches the resolved binary version at connection time.
- Poll with `mcx claude ls --json` using `sessionId` field (not `id`) and `state` field
  (not `status`).
- The main checkout can drift to a feature branch if a worktree session does `git checkout`
  in the parent repo rather than its own worktree. After all impl sessions finish, always
  `git checkout main` in the main worktree before running phases.
- `mcx pr merge` with no args or `--squash` works; verify with `gh pr view N --json state,mergedAt`.
