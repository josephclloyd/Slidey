## What worked

## What didn't
- **`Closes #N` missing from both PR bodies (again, 6th sprint in a row).** Impl sessions consistently omit it. Required manual `gh pr edit` each time before review. This is a known recurring pattern.
- **Main worktree drifted to feature branch after each impl session.** Sessions run `git checkout -b <branch>` in the main worktree rather than a separate worktree, leaving HEAD on the feature branch at session end. Required `git checkout main` before each review phase run.
- **`mcx phase run review` backgrounded instead of returning synchronously on the second call** — possibly a CLI race with prior background tasks. Resolved by re-running; third call worked.
- **`prNumber` stays null after impl session ends** — daemon doesn't auto-populate it. Required `mcx untrack` + `mcx track` re-pair (with 10s wait) before the review phase could find the PR. This occurred for both issues.

## Patterns established
- **Routine after every impl session (before review):**
  1. Check `Closes #N` in PR body — add via `gh pr edit` if missing
  2. `git checkout main` — restore main worktree from feature branch
  3. `mcx untrack N && sleep 10 && mcx track N` — re-pair to pick up `prNumber`
  4. Then run `mcx phase run review --work-item "#N"`
- **`--worktree` flag on spawn doesn't isolate from main checkout** — sessions branch directly in the main worktree, not a separate git worktree. The `worktree` field in `mcx claude ls` is an mcx-internal label, not a separate git worktree path.
